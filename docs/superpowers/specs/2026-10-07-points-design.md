# 子项目 C：积分 设计

来源：第017章 第1–8节积分相关内容（C-17-02、C-17-07 至 C-17-13）。依赖子项目 A（账号激活、使用控制、审计日志、首登）与 B（角色、代理、编号段、编号状态）。
状态：已于 2026-10-07 与用户逐条确认（见第 9 节）。

## 1 范围

做：
- 账号与代理各自的积分余额、积分流水（保留三年）。
- 加分 / 扣分 / 代理转分 / 代理给名下账号充值 / 批量充值，按角色限定。
- 体验期赠送（开关默认关闭）、按账号滚动 24 小时扣 1 分、余额为 0 自动积分暂停、充值自动恢复。
- 登录与业务请求的积分拦截；登录低积分提醒（客户端）。
- 管理后台：余额列、积分操作、积分流水页、体验期设置页；编号状态「已欠费」生效。

不做：客户端左上角头像/昵称/余额显示（D）。

## 2 余额与流水

- `users.points INTEGER NOT NULL DEFAULT 0`、`agents.points INTEGER NOT NULL DEFAULT 0`，整数，永不为负。
- `points_ledger`：`id`、`holder_type`（`user|agent`）、`holder_id`（用户为账号编号，代理为 agent id）、`delta`（正负整数）、`balance_before`、`balance_after`、`kind`、`counterparty_type`、`counterparty_id`、`actor_type`（`admin|agent|system`）、`actor`、`reason`、`batch_id`、`cycle_key`、`created_at`。
- `kind` 取值：`trial`（体验赠送）、`grant`（后台加分）、`revoke`（后台扣分）、`transfer_out` / `transfer_in`（代理间转分、代理给账号充值，各写一条，双方互为 counterparty）、`charge`（每日扣减）。
- 每日扣减以 `UNIQUE(holder_id, cycle_key)`（仅 `kind='charge'`）防重复记账。
- 流水与审计日志一样每天清理，保留 `AUDIT_RETENTION_SEC`（三年）。
- 每次余额变化与其流水在同一事务内写入；积分操作同时写一条审计（`audit_logs`）。

## 3 权限

| 操作 | 最高权限者 / 管理员 | 高级代理 | 低级代理 |
|---|---|---|---|
| 给任意账号或代理加分（凭空增加） | ✓ | ✗ | ✗ |
| 扣分（原因必填，最多扣到 0） | ✓ | ✗ | ✗ |
| 转分给直属下级代理（扣自身余额） | — | ✓ | ✗ |
| 给本人名下账号充值（扣自身余额） | — | ✓ | ✓ |
| 批量充值（多个账号各加相同数） | ✓（凭空增加） | ✓（仅本人名下，扣自身余额） | ✓（同左） |
| 查看流水 | 全部 | 与本人有关 | 与本人有关 |

- 用户之间不能互转；不能从账号转回代理，不能从下级代理转回上级。
- 代理转分 / 充值时余额不足 → 整笔失败（批量充值按总额校验，全有或全无）。
- 资格非激活的代理不能登录，自然不能操作；收款代理必须资格激活。
- 单笔数量为正整数，单笔上限 100000；批量一次最多 1000 个账号。
- 未激活账号可以预先充值；积分从激活起计费。
- 代理自身积分不做每日扣减。

## 4 每日扣减

- 账号字段：`charge_anchor_at`（当前计费起点，可空）、`next_charge_at`（下次扣费时间，可空；空表示当前不计费）、`trial_granted_at`（体验赠送时间，可空）。
- 首次激活：若体验期开启且 `trial_granted_at IS NULL`，赠送设定分数（默认 7），写 `trial` 流水；`charge_anchor_at = 激活时间`，`next_charge_at = 激活时间 + 24h`。
- 可计费条件：已激活、`status='active'`、未过 `expires_at`、余额 > 0。
- 扣减 Worker（进程内，每 60 秒一轮）：
  - 可计费且 `next_charge_at` 为空（刚恢复）→ `charge_anchor_at = now`，`next_charge_at = now + 24h`，不扣。
  - 不可计费 → `next_charge_at = NULL`（停扣，不累计、不追扣）。
  - 可计费且 `now >= next_charge_at`：
    - 逾期不足 24 小时（`now < next_charge_at + 24h`）→ 扣 1 分，`cycle_key` 为该周期的 `next_charge_at`，`next_charge_at += 24h`。
    - 逾期 ≥ 24 小时（Worker 停机错过多个周期）→ 按重新激活处理：不扣，`charge_anchor_at = now`，`next_charge_at = now + 24h`。
  - 扣到 0 即进入积分暂停（由余额推导，不另存状态）；写审计 `points.suspended`。
- 充值使余额从 0 变为 > 0：写审计 `points.resumed`；下一轮 Worker 把计费起点重置为当时。该自动恢复只解除积分暂停，不改变 `status`（管理暂停 / 封禁不随充值解除）。

## 5 拦截与提醒

- 登录（`/api/auth/login`）：在现有封禁 / 暂停 / 到期检查之后，已激活且余额为 0 → `{"code": 10025, "msg": "无积分，无权操作，请充值积分后自动恢复使用！"}`，不发会话。
- 业务请求（`gate.authorize`）：已激活且余额为 0 → 同样返回 10025。客户端拦截器收到 10025 提示该文案并退回登录页（与 10022/10024 的处理一致）；退出不受影响。
- 登录成功响应增加余额字段；余额 > 0 且 < 7 时客户端登录后弹出「您的积分已不足，请尽快联系客服增加积分！」，可关闭继续使用。
- 优先级：封禁 > 管理暂停 / 到期 > 未完成首登 > 无积分。
- 旧客户端：收到 10025 只显示通用登录失败提示（新客户端发布前的已知限制）。

## 6 体验期设置

- `settings` 键值表（或等价）：`trial_enabled`（默认 `false`）、`trial_points`（默认 7，1–100）。
- 首次扣减延迟与扣减周期固定 24 小时，设置页只读显示；每账号仅一次体验赠送。
- 开关与分数仅影响此后首次激活的账号；关闭 / 重新开启都不补发、不追溯。
- 仅最高权限者与管理员可查看与修改，修改写审计。

## 7 管理后台

- 账号列表：增加「积分余额」列；「编号状态」中「已欠费」生效（已激活且余额为 0），「已激活」改为已激活且余额 > 0。
- 账号操作：后台人员「加分」「扣分」；代理「充值」。多选后「批量充值」。
- 代理列表：增加代理余额；后台人员「加分」「扣分」；高级代理在「编号划拨」旁增加「转积分给下级」。
- 新页面「积分流水」（筛选：账号 / 代理、类型、时间）；代理只见与本人有关的流水。
- 新页面「体验期设置」（仅后台人员）。
- `/admin/me` 对代理返回本人余额。

## 8 上线

- 迁移：`users.points`、`agents.points` 默认 0；老账号上线即为余额 0 → 已欠费，无法登录。上线后用批量充值为需要继续使用的账号充值（运维步骤写入 DEPLOY / README）。
- 先发布带 10025 处理与低积分提醒的新客户端，再部署后端（否则旧客户端只见通用失败提示）。
- 到期时间（A 的 `expires_at`）保留，与积分独立，任一不满足都不可使用。

## 9 已确认决定（2026-10-07）

- Q1：代理（高级与低级）可用自身余额给本人名下账号充值；高级代理还可转给直属下级代理。
- Q2：老账号也按积分计费，余额 0 即暂停；上线后用批量充值处理。
- Q3：余额为 0 不能登录；使用中扣到 0 时下一次操作提示并退回登录页。
- Q4：最高权限者和管理员可扣分，原因必填，最多扣到 0；代理不能扣。
- 默认值（用户确认）：体验期只开关与赠送分数可改；未激活账号可预充；代理积分不每日扣；到期时间保留；客户端需发版。
