# 子项目 B：后台角色、代理与账号编号段 设计

来源：第017章 第1、2、3、5、7、8节（C-17-04/05/06/16/17/18/19）。依赖子项目 A（账号激活状态、审计日志、管理后台）。
状态：Q1–Q7 已于 2026-10-06 与用户逐条确认（见第 7 节）。

## 1 范围

做：
- 后台三类登录身份：最高权限者（唯一）/ 管理员 / 代理，统一登录同一管理后台，按角色显示菜单与数据。
- 代理资料：名称（全局唯一，改名或取消资格后旧名保留一年）、地区标签（省级/市级/VIP）、级别（高级/低级）、上级代理、资格状态（激活/暂停/取消，含变更人、时间、原因）。
- 账号编号段：分配（管理员→代理）、划拨（高级代理→其直属下级，不可撤回）、回收（代理资格取消后回收其未激活编号并解除上下级关系）；总配额 / 已激活 / 未激活统计。
- 代理激活本人名下账号（复用 A 的激活逻辑）；首次激活时记录直接/间接/次间接上级（界面只展示直接上级）。
- 授权：最高权限者把「代理改名」授予指定管理员，可撤销；被授权者不得转授。
- 所有操作写审计日志（A 已建表，保留三年）。

不做：积分与积分划转（C）、客户端用户信息区（D）、通知渠道（仍只记日志）。

## 2 账号编号

- 新号统一为 7 位纯数字 `1000000`–`9999999`（不允许前导 0）。存量账号编号不改，不属于任何号段，`agent_id` 为空。
- 编号段用起止两个数表示（含两端），单次分配上限 10000 个。
- **分配即建档**：分配编号段时，段内每个编号立即建为「待激活」账号（预置 123456，`pending=True`），归属该代理。段内任一编号已存在且不是「无归属的待激活账号」（回收后的号）→ 整次分配拒绝，提示冲突编号。回收后的号可再次分配，直接改归属。
- 归属以账号上的 `users.agent_id` 为准；`segment_ops` 只是分配/划拨/回收的流水，用于展示与审计，不参与判定。

## 3 角色与权限

| 能力 | 最高权限者 | 管理员 | 代理 |
|---|---|---|---|
| 账号激活/暂停/封禁/重置/删除 | 全量 | 全量 | 仅激活本人名下账号；只读本人名下账号 |
| 新建代理、改地区标签/级别/上级 | ✓ | ✓ | ✗ |
| 代理资格激活/暂停/取消 | ✓ | ✓ | ✗ |
| 编号段分配给代理、回收 | ✓ | ✓ | ✗ |
| 编号划拨 | ✗ | ✗ | 高级代理：本人名下未激活编号 → 直属下级 |
| 代理改名 | ✓ | 需最高权限者授权 | ✗ |
| 授权管理、管理员账号管理 | ✓ | ✗ | ✗ |
| 操作日志 | 全部 | 全部 | ✗ |

- 所有接口在服务端校验角色与数据范围，前端隐藏菜单只是辅助。
- `X-Admin-Key`（运维密钥）视为最高权限者。
- 最高权限者只能有一个：服务器命令 `manage.py set-super <用户名>` 指定，原最高权限者自动降为管理员；后台界面不能转让。升级后现有管理员全部为普通管理员，部署后需执行一次该命令。

## 4 代理

- 登录：代理是 `admins` 表中 `role='agent'` 的登录身份，用户名即代理名称，只能登录管理后台，不能登录客户端。代理若自己用软件，从自己名下拿一个编号按普通用户流程使用。
- 级别：`senior`（高级）/`junior`（低级），单独存储。只有高级代理可以做别人的上级、向下划拨编号；低级代理不能有下级。把高级改为低级时，若仍有下级则拒绝。上级必须是资格状态为「激活」的高级代理，不能是自己或自己的下级（禁止成环）。
- 地区标签：`province|city|vip`，只用于显示和筛选。
- 资格状态：
  - 激活：正常使用。
  - 暂停：不能登录后台；名下账号不受影响。
  - 取消：不能登录后台；名下未激活编号显示「待回收」；名称进入一年保留期。回收前可恢复为激活，恢复后名称仍归本人。
  - 每次变更记录变更人、时间、原因（必填）。
- 名称：全局唯一（不区分大小写，去首尾空格，1–20 字符）。改名或取消资格时旧名写入保留表，保留一年；新建或改名时与在用名称或保留期内名称冲突 → 「该名称已被使用」。名称本人恢复资格时，从保留表删除自己的旧名。
- 回收：仅对资格已取消的代理。名下所有未激活账号的 `agent_id` 置空（变为无归属待激活号，可再分配）；其下级代理的 `parent_agent_id` 置空；已激活账号保持原归属不变。

## 5 编号状态（第5节五态）

管理列表的「编号状态」由数据推导，不另存：
- 待激活（即已分配）：有归属代理、`first_activated_at IS NULL`、代理资格未取消
- 已激活：已激活且余额 > 0（C 之前全部视为已激活）
- 已欠费：已激活且余额 = 0（C 实现后生效）
- 待回收：所属代理资格已取消且未激活
- 未分配：无归属的待激活号（回收后的号）

使用控制（正常/暂停/封禁）仍为 A 的独立字段 `status`。

## 6 数据模型

- `admins` 增加 `role TEXT NOT NULL DEFAULT 'admin'`（`super|admin|agent`）。迁移后现有管理员均为 `admin`。
- `agents`：`id`、`admin_id UNIQUE`（登录身份）、`name`、`name_key UNIQUE`（规范化名称）、`region`、`tier`、`parent_agent_id`、`status`、`status_by`、`status_at`、`status_reason`、`created_at`。
- `agent_name_reservations`：`name_key PRIMARY KEY`、`agent_id`、`reserved_until`。
- `segment_ops`：`id`、`op`（`assign|transfer|recycle`）、`start_no`、`end_no`、`count`、`from_agent_id`、`to_agent_id`、`actor`、`created_at`。
- `users` 增加 `agent_id`（当前归属代理）、`activated_by_agent_id`、`agent_chain_json`（首次激活时的直接/间接/次间接上级 id，最多三层）。
- `admin_grants`：`admin_id`、`grant`（本期只有 `agent.rename`）、`granted_by`、`granted_at`、`revoked_at`。
- 统计（按代理）：总配额 = 名下账号数；已激活；未激活 = 总配额 − 已激活。

## 7 已确认决定（2026-10-06）

- Q1：现有编号无规律，老账号不进号段；新号统一 7 位纯数字，号段为起止数。
- Q2：分配时一次性建好待激活账号；「已分配」与「待激活」合并。
- Q3：代理只是后台身份，积分单独记（C 实现）；代理不是客户端账号。
- Q4：最高权限者唯一，由服务器命令指定；现有管理员降为普通管理员。
- Q5：高级/低级单独存储，与上级关系并存；只有高级可有下级、可向下划拨。
- Q6：管理员在代理相关操作上与最高权限者相同；最高权限者额外管理管理员与授权。积分发放权限在 C 再定。
- Q7：代理被取消资格时，名称同样保留一年。

## 8 实施划分（进入计划时细化）

1. 角色与登录：`admins.role`、`set-super` 命令、依赖注入的角色守卫、`/admin/me` 返回角色。
2. 代理资料：增删改、级别/上级校验、资格状态、名称唯一与保留期、改名授权。
3. 编号段：分配建档、划拨、回收、统计、`segment_ops` 流水。
4. 账号与代理：代理激活名下账号、首次激活关系链、账号列表增加归属代理与编号状态及按代理筛选。
5. 管理后台前端：按角色显示菜单；代理管理、号段、授权、管理员管理页面；代理视角的「我的账号」。
